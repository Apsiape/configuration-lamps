# Amenable groups with nearly exponential sofic profile: Lean core of Part I

This directory proves selected Part I results of the paper in Lean 4. It is the Lean core of Part I, not a formalization of the whole paper.

## What is checked

`Statements.lean` freezes the selected propositions, `Proofs.lean` proves them, and `Audit.lean` checks that they match the original declarations below and prints their axioms. A row credits only the form stated in it. Γ is the subgroup of Perm(V×S₃) generated by the five permutations p, q, t, c, a. Theorem 3.3 is the detailed Theorem A. Some declaration names and docstrings keep older numbering; the first column uses the paper's numbering.

The numbered wrappers are `PaperProofs.<name>`, with the frozen types `PaperStatements.<name>`; `PaperProofs.theorem_A` is the partial combined result and `PaperProofs.thm_sweep` has the explicit sweep premise.

**Conditional premise.** `Lamps.PermSweepBound` is defined in `vendor/finite-lean/FiniteLean/Hypotheses/PermSweepBound.lean`. It is a proposition, not an axiom, and it is not proved here:

```lean
def PermSweepBound : Prop :=
  ∀ (Ω : Type) [Fintype Ω] [DecidableEq Ω] (N : ℕ) (x c : Fin N → Perm Ω),
    (∀ i, c i ^ 3 = 1) → (∀ i, x i ^ 2 = 1) → (∀ i, x i * c i * x i = (c i)⁻¹) →
    (∀ i, (1 : ℝ) / 4 ≤ dH (c i) 1) →
    (∀ i (h : Fin 6) (g : Fin N → Fin 6),
      dH (commG (nfG (x i) (x i * c i) h) (sufW i fun j => nfG (x j) (x j * c j) (g j))) 1 ≤
        1 / 20000) →
    (N : ℝ) / 16 ≤ Real.logb 2 (Fintype.card Ω)
```

It is the entropy step of the paper's sweep proof. Only Theorem 2.3 and its wrapper take it, as an explicit premise; Theorem 3.3 does not use it.

**Conventions:** finite profiles use normalized Hamming distance with ε = 1/r and positive model sizes; unitary bounds use the normalized Hilbert–Schmidt norm (Tr X*X/D)^(1/2), and an empty dimension type makes the separation hypothesis unsatisfiable. The vendored entropy results are finite dimensional, use natural logarithms and keep the positive-definiteness hypotheses shown in their types; no infinite-dimensional operator-entropy bridge is claimed.

**Not formalized:** the identification of Γ with the full wreath product (⊕_V S₃)⋊A (generation by the five elements is Lemma 3.1(b)); the exact Z² quotient and kernel description of Lemma 3.1(c) (the amenability proof uses a locally finite-by-abelian description instead); finite presentation (Proposition 7.1 and Theorem 3.3(d)); Propositions 7.2–7.3; the ladder results of Section 8; the `PermSweepBound` entropy step and the elementary-letter 1/60000 sweep variant; the unitary conclusions of Theorem 2.1 and Corollary 2.2 as selected statements (the source proves the unitary counting criterion as `Lamps.counting_criterion_unitary`, relative to the proved interfaces `UnitaryS3Round`, `UnitaryPhaseRobust` and `UnitaryMargin`, and uses it for Theorem 3.3(c); it is not a selected root) and the general unitary sector statement of Lemma B.2; Lemmas 6.1–6.2, A.1–A.2, Proposition A.3 and Lemma C.4 as numbered statements (only supporting source results exist); Parts II–III and Appendices C–I. `evidence/PAPER-COVERAGE.tsv` lists every numbered result of the paper.

## Trust base

- Lean 4.35.0 and Mathlib commit `56a005855ea17e0b0958f73ec801ae140b0a1679`. The pins are in `lean-toolchain`, `lake-manifest.json` and `UPSTREAM-PINS.json`; `LIBRARY-MODULES.txt` lists the vendored shared-library modules.
- Every declaration in the table and every numbered wrapper depends only on Lean's three standard axioms, `propext`, `Classical.choice` and `Quot.sound`. `AXIOMS.txt` is the exact axiom output.
- The proofs pass two independent kernel checkers, `leanchecker` and `nanoda`.
- `evidence/KERNEL-REPLAY.json` records the kernel replay (export digest, checker binaries, exits) and the run of the reproduce commands on 6 November 2026; `evidence/CERTIFIED-SOURCE-HASHES.json` pins the checked sources. `evidence/replay.sh` runs leanchecker over the vendored library modules only; it is not the two-checker replay recorded in `KERNEL-REPLAY.json`.

## Reproduce

With the pinned Lean toolchain on PATH, Git available for fetching the pinned dependencies, and one compiler job at a time, run from `lean/`:

```sh
export LEAN_NUM_THREADS=1
lake exe cache get
lake build
lake env lean -j1 -M6144 Audit.lean
```

`lake exe cache get` fetches the Mathlib build cache and `lake build` builds the core. `Audit.lean` prints the type of each checked declaration followed by its axioms; the axiom lines match `AXIOMS.txt`.
